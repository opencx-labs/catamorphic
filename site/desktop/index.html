// what it is

One place for the whole loop

Read, think, direct, judge, all without leaving. The surfaces agents need to do real work are the same surfaces you use every day.

Projects hold any kind of work

A project is a folder you can see in Finder: documents, notes, data, plans, code, automations, and apps, in any mix. Import an existing folder or clone a repo and its contents are adopted as-is. The automation workspace appears the first time you ask for one, not before.

Real work surfaces

Web tabs with your logins and profiles, real terminals (Ghostty's engine), an editor, and chats: all first-class tabs in one workspace, tileable side by side. Agents and you share the same surfaces.

Bring your own agents

Claude Code, Codex, and API models run side by side as named agents, on your accounts, your keys, your existing logins. Switch the agent or its effort per chat from the command palette. No middleman subscription.

Agents that show their work

Agent-driven tabs and terminals stay visible with a quiet accent ring, and every page action flashes on the element it touches. Agents can open a page behind your chat to show you something, and point at the exact element they mean. One click takes any surface over; the agent notices and adapts.

Tracked like code, without the ceremony

Every project is a git repository underneath. Agent turns that change files land as checkpoints, linked projects sync with GitHub in the background, and agents can push a branch and open a pull request when a change deserves review. Agents report in plain language; you never have to see git.

Review what matters

Nothing an agent does is hidden: pull up a diff whenever a change deserves scrutiny, per worktree or per pull-request file. Skim the routine, dig into the critical, redirect the agent from the diff. Track-changes for prose, so writers get the same, is in progress.

// also in the box

Deep where your work is deep

The same app serves a writer and a working engineer. Dev surfaces degrade quietly when a project has no code; nothing hides behind a mode switch.

A real dev shell

Claude Code behaves exactly as it does in the CLI: your repo's CLAUDE.md, .claude skills, commands, and settings all load. Worktrees are listed and diffable, the sidebar shows open pull requests with per-file patches, and terminals and the embedded browser round out the loop.

Agents your project defines

A project can commit its own agents as files: a definition plus a persona document, authored and reviewed like any other work product. Before a project agent spends your personal credentials, you approve it explicitly, and any change to what you approved asks again.

Your team's server, as a folder

Paste the connect link from an invite and a folder on your machine becomes a working copy of what your role lets you see: company docs read-only, your own customers' notes and decks read-write. Sync pulls, Ship pushes with version checks, and every store file keeps its history. Your own agents can reach the same project over MCP.

Automations and apps, on demand

Ask for an automation and you get a durable workflow: it can run on triggers, like a chat finishing or a terminal going idle, and any workflow can become a tool your agents call. Ask for a dashboard and an agent builds a sandboxed app on top, with a polished UI kit and storage of its own.

// how a session goes

Delegate without disappearing

The point isn't autonomy theater. It's real work, visible, with you in the loop exactly where you want to be.

1

Ask, from anywhere

Cmd+T opens the palette: search, navigate, or just type what you want done. Long input becomes a message to an agent.

2

Watch it work

The agent opens tabs, runs terminals, edits files. Each surface chips onto its chat, live and visible, never hidden.

3

Steer when you want

Take over any surface mid-task. Queue follow-ups while the agent runs. Answer its questions when it's genuinely blocked.

4

Judge, then land it

Skim what the session produced and dig into the changes that matter. Every turn is already checkpointed and synced in the background; ask for a pull request when a change deserves review. Scrutiny where you choose, not a toll gate on every line.

workspacelive

01 / your machine

Local-first, by construction

State lives on your disk. Profiles keep work and life separate: each owns its projects, logins, theme, shortcuts, and agent roster.

02 / your rules

Everything is configurable, even by your agents

Keybindings, sidebar, and theme are plain files, watched live. Ask an agent to "make the accent purple" or "add a Docs section" and it edits the same files you would.

03 / honest boundaries

Contained, not omnipotent

Agents run under real trust boundaries: sandboxed execution, permission scopes, and credentials that are never silently agent-reachable. Control you can see, limits you can set.

// where it's going

Direction, stated plainly

Two things the current design points at but does not ship yet. Neither exists today; both are why the seams are shaped the way they are.

A stock self-hostable server

The framework side exists today: roles as committed files, member tokens, the project MCP endpoint, the project store, and the desktop connecting to any host that embeds Catamorphic. What is missing is the packaged server binary you just run, plus remote agents speaking the Agent Client Protocol. Roadmap, not shipped.

Review-mode collaboration

Members without commit rights already propose changes that open as pull requests on their behalf. Still to come: PR-first sync for shared projects and review rendered natively in the app. Roadmap, not shipped.

Built in the open

Catamorphic Desktop is in active development and permissively licensed. It is also the framework's reference implementation: everything you see in the app is built on the same open packages you can embed in your own product.
